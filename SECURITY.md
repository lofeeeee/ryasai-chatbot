# Security Policy

## Reporting a Vulnerability

Report security vulnerabilities by emailing the maintainer at **security@ryasai.com**.

- **Do not open public GitHub issues** for security reports.
- Acknowledgement within 48 hours.
- Critical vulnerabilities fixed within 7 days; lower severity on a best-effort schedule.
- Include reproduction steps, affected version, and impact assessment in your report.

## Scope

This policy covers the application source code in this repository only. Vulnerabilities in third-party dependencies should be reported to their upstream maintainers.

## Supported Versions

Only the most recent minor release line receives security fixes.

This section deliberately names no version. A literal here goes stale the moment
a release ships and keeps assuring readers long after it stops being true (it
read `0.4.x` for the whole of the 1.x series). Maintainers: keep it that way —
describe the release line in words, and resist adding a number to make it feel
more precise; "the latest minor" is a policy, not a version.
